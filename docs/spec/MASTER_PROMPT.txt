
AIRAVAT
Indian Securities Brokerage & Trading Ecosystem | Master Project for Claude Code
AIRAVAT will be developed as a completely independent Indian brokerage company and technology ecosystem. It will have its own identity, infrastructure, trading engines, administration, client applications, security architecture and regulatory operations.
There will be no integration, association, shared branding, shared infrastructure or dependency involving 777, Raptor, EMIL or any other existing project.
The goal is to build AIRAVAT as a serious competitor to Zerodha, Groww, Dhan, Angel One, Upstox, FYERS, ICICI Direct, Kotak Neo, 5paisa and other major Indian brokerages.
The master specification below combines the previous business and technical blueprints, expands the product into a full brokerage ecosystem, and adds advanced features drawn from the established capabilities of Indian trading platforms. I cannot verify the competitors' live October 2026 feature inventories here, so Claude Code is instructed to conduct a current, source-backed competitive audit before finalizing implementation.
This is written as an execution brief for Claude Code, not just a list of ideas. It includes architecture, modules, workflows, regulatory gates, business operations, user interfaces, security, testing, deployment and instructions to avoid incomplete or decorative functionality.

PART I. MISSION AND NON-NEGOTIABLE RULES
1. The AIRAVAT Vision
Build AIRAVAT as a complete, institutional-grade Indian brokerage platform capable of serving first-time investors, retail traders, professional derivatives traders, high-net-worth individuals, active investors, algorithmic traders, authorized persons, corporate clients and eligible institutional participants.
AIRAVAT must combine the accessibility of a beginner-friendly investment app with the sophistication of a professional trading terminal.
The entire experience must feel like one coherent financial institution, not a collection of disconnected websites and dashboards.
The system must support the full lifecycle of a brokerage client:
Discovery → Registration → KYC → Verification → Account Activation → Funding → Market Discovery → Trading → Risk Management → Settlement → Portfolio Management → Reporting → Taxation → Support → Retention.
The company must also have the operational systems necessary to function as a regulated broker, including finance, dealing, surveillance, compliance, clearing, settlement, depository integration, accounting, customer service, management reporting and disaster recovery.
2. Project Isolation
AIRAVAT is a new, independent project.
Do not reference, import, connect, clone, reuse credentials from, or create dependencies on any unrelated company, brokerage, platform, AI product or previous project.

Use explicitly labeled configuration placeholders until genuine details are supplied and verified.
3. Engineering Commandments
Never silently omit a requested module.
Never substitute a decorative interface for working functionality.
Never use fake market prices presented as live.
Never fabricate an exchange connection.
Never imply that AIRAVAT has obtained a license or exchange approval before verification.
Never expose client funds, credentials or private information.
Never execute live trades without proper authorization and controls.
Never bypass the RMS.
Never allow an AI agent to override regulatory safeguards.
Never implement an irreversible financial action without appropriate authorization, validation and audit records.
Never confuse a successful API request with a successful exchange execution.
Never hardcode secrets or credentials.
Never deploy untested critical changes.
Never silently delete working functionality while adding new modules.
Never claim production readiness without evidence.
Never claim that a module is complete when it contains only mock screens.
Never expose sensitive administrative functions to ordinary users.
Never use copyrighted third-party branding, code or proprietary data without authorization.
Never hide unfinished work or failed tests.
Never sacrifice financial correctness for visual effects or delivery speed.
Fundamental principle: Real functionality, correct financial records, operational resilience and regulatory compliance take precedence over visual sophistication.
